# Mobile cryptographic reference fixtures

These files exercise the actual mobile boundary, separately from the Rust FFI.
All identities, keys, accounts and plaintexts are disposable fictional test data.
The installed application does not contain or start a JVM.

Copied unchanged from Monogram Android commit
`be6876c045163e32fe07a84416621770b0964b30`, GPL-3.0-or-later:

`Bridge.java` provides an in-memory records transaction and line interface solely
for the comparison. `build.sh` compiles the unchanged JNI source against the same
libomemo-c/OpenSSL package as desktop. The Rust test establishes sessions in both
directions, exchanges Unicode messages and delivers messages out of order.

`payload-vectors.json` was generated by `vectors/GeneratePayloadVectors.java`
against freshly compiled mobile `Omemo2Payload.java` (SHA-256
`4a71ba835a1250f2a14e4ff4d9dea420c039689d00a10903bc36add77366ceb2`).
The explicit key consists of bytes 0 through 31 and is never used outside tests.
The vectors compare complete HKDF/AES-CBC/HMAC output, including empty text,
Unicode and SCE with a protected reply. The regular Rust suite checks them without
the mobile checkout or Maven dependencies. To regenerate, compile that Java file
and the generator using the mobile xmpp-core classes/dependency classpath, then
run `com.negzero.monogram.xmpp.GeneratePayloadVectors` and capture stdout.

The Nix package builds/runs the JNI comparison with JDK 21 explicitly; a plain
`cargo test` run without `MONOGRAM_MOBILE_CRYPTO_FIXTURE` does not establish JNI
interoperability. Live PEP/wire tests additionally require the disposable Prosody
fixture; these comparisons alone do not establish complete encryption UI parity.

`vectors/ReactionEmojiReference.java` generates `assets/reaction-emoji.tsv` by
compiling the baseline mobile `EmojiData.java` and walking its actual data/colored
data/alias arrays with mobile's canonicalization rule. To regenerate, compile
those two sources with JDK 21 and run `ReactionEmojiReference`, capturing stdout.
The table is included at compile time; no JVM or mobile checkout is needed at
runtime. Input attribution/license is recorded in `assets/NOTICE.md`.

`poll-vectors.json` is generated by the mobile test-only
`com.negzero.monogram.xmpp.GeneratePollVectors` against freshly compiled
`PollDefinition`/`Omemo2Payload`, then read by Rust's poll tests. It includes
bodyless/translated/unmarked fallback cases, scalar/emoji limits, invalid mappings
and closure, plus seven deterministic protected SCE payloads and a historical
duplicate-body payload (fixture key bytes 0 through 31). Run the generator with the mobile test runtime classpath after
`mvn -f xmpp-core/pom.xml -Dtest=PollDefinitionTest test`. Its stdout is the JSON.
The mobile codec source remains in the adjacent mobile repository, rather than
a second drifting Java implementation copied into desktop.

Two cases use the actual mobile send builder, covering a bodyless poll and a poll
with accompanying text, reply quoting and independent fallback ranges. Rust also
normalizes those stanzas into the displayed poll/message/reply model.

`legacy-poll-vectors.json` is exported by the actual mobile `MonogramPolls.Poll`
encoder/parser (application source at `9cde459ac`, GPL-3.0-or-later), through the
test-only `MonogramPollsTest.exportLegacyCodecVectorsForDesktop`. Set the test JVM
property `monogram.legacy.poll.vectors` to a local output path. The 20 cases include
all 32 mappings, multiline descriptions/options, malformed indentation/footers,
variation selectors, Java UTF-16 bounds and a 40000-unit body that cannot grow a
legacy closure. Rust checks matching semantics, exact legacy serialization,
format isolation, cached-message recovery and reply handling.

`forward-vectors.json` is generated by mobile's test-only
`com.negzero.monogram.xmpp.GenerateForwardVectors` against the actual
`ForwardedContent`, `XmppMessage` and `Omemo2Payload` sources. After
`mvn -f xmpp-core/pom.xml -Dtest=ForwardedContentTest test`, run the generator with
that test's runtime classpath and capture stdout. Forty-two received-wire cases
cover full JIDs/Unicode labels, canonical and malformed dates/prefixes, literal
whitespace, XML line-ending normalization, empty content, standalone forwarded
messages, annotations, translated bodies and inner-ID/action isolation. Eight
also contain deterministic protected SCE vectors (fixture key bytes 0 through 31).
Reference XML with a language-specific-only body explicitly declares its default
language so the fixture does not depend on the test runner's desktop locale.
