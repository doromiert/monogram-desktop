IN PROGRESS — First-attempt downloads and uploads stall for all media/stickers
  Media is recognized and a download/preparation spinner appears, but the job
  sometimes makes no further visible progress. Determine whether HTTP transfer,
  cache verification, preview preparation or UI observation is stalled. Keep
  cancellation/retry usable and show a bounded, meaningful failure if stalled.
  Latest 18:11 video diagnosis: production worker twice timed out after 30 s
  before HTTP headers, with zero bytes. A later retry downloaded/decrypted/
  authenticated all 1,407,353 bytes in 0.81 s. DNS/TCP/TLS checks pass. This
  establishes an intermittent response timeout, not its remote/network cause.
  Added safe timeout/connect categories; URLs and encryption keys are not logged.
  New report: every first user start needs cancel/error then retry, including
  uploads and stickers. The affected host can stall before response headers.
  Desktop forced HTTP/1.1 also reproduces the timeout; forcing that protocol is
  not a verified fix. Android already uses HTTP/1.1 and independently reproduces
  intermittent cold-process failure. Continue connection-stage diagnosis; do not
  mark a single successful retry or protocol change as resolution.
